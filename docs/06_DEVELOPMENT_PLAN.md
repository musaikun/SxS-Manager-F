# 開発計画書

## 🎯 開発方針

### アジャイル・イテレーティブ開発

- **スプリント**: 1〜2週間
- **優先順位**: 高→中→低の順に実装
- **MVP（最小実用製品）**: Phase 1完成

### 基本原則

1. **動くものを早く作る**
   - 完璧を目指さず、まず動作させる
   - イテレーションで改善

2. **シンプルに保つ**
   - 過度な設計をしない
   - 必要になってから追加

3. **テストしながら作る**
   - 実装→手動テスト→修正のサイクル

## 📝 開発ルール

### コーディング規約

1. **Dartスタイル**
   - `flutter_lints`に従う
   - `dart format`で自動整形

2. **命名規則**
   - クラス: PascalCase
   - 変数・関数: camelCase
   - ファイル: snake_case

3. **ディレクトリ構造**
   ```
   lib/
   ├── features/          # 機能ごと
   │   ├── auth/
   │   │   ├── data/     # Repository
   │   │   ├── domain/   # Model
   │   │   └── presentation/ # UI
   ├── core/              # 共通
   └── main.dart
   ```

### Gitルール

1. **ブランチ命名**
   - `claude/feature-name`
   - 例: `claude/auth-login`

2. **コミットメッセージ**
   ```
   feat: 新機能追加
   fix: バグ修正
   docs: ドキュメント更新
   refactor: リファクタリング
   test: テスト追加
   ```

3. **プッシュ**
   - 機能完成時
   - 大きな変更の節目
